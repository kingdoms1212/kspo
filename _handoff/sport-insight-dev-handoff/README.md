# SPORT INSIGHT 개발 명세 · 코딩 에이전트 프롬프트
버전: 1.0 | 작성·자료 설명 재확인일: 2026-09-11

## 목적
최종 디자인 시안을 **대시보드 / 프로그램 분석 / 시설 현황** 3개 화면으로 개발하기 위한 명세 패키지다.
서비스 사용자는 정부·지자체·공공기관 담당자이며, 개인 운동 추천 앱이 아니다.

**이 패키지는 실행 가능한 완성 앱이 아니다.** 화면 명세, 데이터 계약 초안, 작업 프롬프트, 검수 기준, 기존 CSS와 시안 이미지를 제공한다.
공공데이터 원본 CSV·JSON과 대한민국 행정경계 GeoJSON은 포함하지 않는다.

## 가장 중요한 결정
- 제품에는 LLM·AI API, 추천 이유 생성, AI 인사이트, 효과 예측을 넣지 않는다.
- “프로그램 추천”은 실제 등록 강좌를 조건으로 걸러 정렬한 결과다. 새 사업·강좌를 생성하지 않는다.
- 보고서 메뉴를 만들지 않는다. 대시보드·차트·프로그램표·시설목록에 XLSX 내보내기를 둔다.
- 최종 이미지의 배치·색감은 유지하되, 이미지의 수치·사진·라벨을 실데이터로 복제하지 않는다.
- 데이터가 없으면 null/확인 필요를 표시한다. 시연 데이터는 모든 화면과 엑셀에 “시연 데이터”로 구분한다.
- 프로그램 수강료를 시설 운영비로 사용하지 않는다. 예산 검토는 검증된 월·1인 수강료를 사용한 단순 산식이다.

## 사용 순서
1. 신규 저장소는 이 패키지의 내용을 프로젝트 루트로 복사한다. 기존 저장소는 AGENTS.md/CLAUDE.md를 덮어쓰지 말고 규칙을 병합한다.
2. `AGENTS.md`, `docs/00-scope.md`, `docs/01-screen-spec.md`를 검토한다.
3. Codex에는 `prompts/CODEX-START.md`, Claude Code에는 `prompts/CLAUDE-CODE-START.md`를 첫 메시지로 전달한다.
4. `prompts/00-bootstrap.md`부터 `06-qa.md`까지 한 단계씩 실행한다.
5. 각 단계의 diff·테스트 결과를 확인한 후 다음 단계로 넘어간다.
6. 실제 데이터는 먼저 원본 컬럼·단위·중복·기준시점을 검증하고 `docs/02-data-contract.md`의 정규화 규칙에 연결한다.

## 두 도구를 함께 사용할 때
한 작업은 한 도구가 구현하고 다른 도구가 검토하는 방식을 권장한다.
동일 브랜치·동일 파일을 두 에이전트가 동시에 수정하지 않는다.
병렬화한다면 데이터 계약·공통 컴포넌트를 먼저 확정하고 별도 브랜치 또는 worktree로 화면 작업을 나눈다.
코드 커밋·푸시·배포는 별도 승인 없이는 실행하지 않는다.

## 실제 데이터 검증 범위
이번 확인은 제공된 데이터 상품 페이지의 설명을 기준으로 했다.
원본 데이터 전수 검증, 실제 컬럼 정의서 매핑, 이용허락조건 확인, 통계 중복 제거 검증은 아직 완료하지 않았다.
따라서 계약의 영문 필드명은 **제안한 내부 스키마**이며, 원본에 같은 이름의 컬럼이 있다는 뜻이 아니다.
