기획 목표와 현재 구현 범위

구분내용
기획 목표지역별 이용 통계를 근거로 공공시설을 활용한 스포츠 프로그램을 설계하고, 지역사회와 스포츠의 선순환을 만듭니다.
현재 구현담당자가 지역 통계를 확인하고 종목·시설·운영 정보를 직접 선택·입력하는 검토용 계획서 도구입니다. Gemini 기반 지역 현황 요약과 입력 계획의 AI 검토를 선택적으로 제공하며, 실제 개설 확정을 대신하지 않습니다.
지역·시설 범위기본 배치는 서울이며 대시보드 적재도 서울로 제한됩니다. 설계 후보는 지역·종목·정상운영 조건을 사용하고 공공시설 전용 조건은 없습니다.
보관 방식업무 조회 데이터는 CSV·메모리 캐시, 계획서는 선택한 AI 검토와 함께 브라우저 최근 5건에 보관합니다. 지역 AI 요약은 서버 파일 캐시에 24시간 보관합니다. Django 기본 SQLite 설정과 업무 데이터 저장은 구분됩니다.

패키지 책임과 유지보수 경계

View는 요청 검증과 응답, Service는 필터·집계, Model/Repository는 CSV 적재, Template은 화면 표시를 맡습니다.

planning/reports.py는 전달받은 통계와 입력으로 보고서를 구성하며 CSV를 다시 조회하지 않습니다. planning/snapshots.py는 결과 서명·검증을 담당합니다. 설계 Form과 후보 선정은 dashboard/planning.py에 남아 있습니다.

runtime/targets.py가 기능별 공개 갱신 함수를 조립하고, 실행 관리자는 캐시 내부 값에 직접 접근하지 않습니다. shared는 구체적인 업무 패키지를 import하지 않는 지역 선택 정책입니다.

시스템 아키텍처

Django 서버 렌더링에 HTMX 부분 갱신과 fetch 기반 설계를 결합합니다. 브라우저가 CSV를 직접 읽지 않고 서버가 가공한 HTML·JSON을 받습니다.

구성동작
화면과 요청HTML·HTMX·일반 JavaScript·ECharts. 별도 React 앱이나 DRF 중심 API 구조는 아닙니다.

AI 외부 연동버튼 클릭 → dashboard/ai_views → 공통 AI 인터페이스·팩토리 → 공급자 모듈 → Gemini API → 응답 검증. 키는 서버에서만 사용합니다. 기존 AI_REVIEW_MODE·GEMINI_MODEL·GEMINI_TIMEOUT_SECONDS도 호환되며 새 설정이 우선합니다.
AI 저장 경계지역 요약은 파일 캐시, 프로그램 검토는 입력에 연결한 서명 토큰, 완성된 계획서는 브라우저 스냅샷으로 구분합니다.
서버 기동·데이터 준비·저장 방식

워커 초기화 뒤 CSV 사전 적재와 스케줄러를 시작합니다. Gunicorn master 단계에서 갱신 스레드를 만들지 않아 fork 이후 잠금·스레드 불일치를 피합니다.

준비 상태는 최초 적재 완료 여부를 기준으로 판단합니다. 갱신 중에도 기존 목록이 있다면 ready 상태로 조회할 수 있습니다. loading·missing은 503, stalled는 요청을 통과시켜 직접 적재를 허용합니다.

파일별 캐시가 독립적이므로 한 요청이 여러 데이터셋의 동일 세대를 반드시 읽는 전역 트랜잭션 구조는 아닙니다. BATCH_STORAGE_MODE=db는 확장 지점이며 DB 모델·저장기·조회 전환이 완료되었다는 뜻은 아닙니다.

배치 검증과 세대 공개 과정

UTF-8 BOM을 허용해 원본을 읽고 필수 지역 열을 검사합니다. 짧은 행, 지역 코드 누락·비숫자 값·시도/시군구 코드 불일치를 제외하며 사유별 건수를 기록합니다. 대상 행이 0건이면 게시를 거부합니다.

독점 잠금 파일로 동시 실행을 제한하고 오래된 잠금은 6시간 기준으로 처리합니다. .part 작성 후 flush·fsync와 대상 범위 검증을 거쳐 파일을 교체합니다. manifest에는 generation·수정시각·크기·SHA-256·행 수·제외 건수가 담깁니다.

준비본 생성 실패 시 .part를 정리하고 로그를 남깁니다. 파일 교체 도중 장애는 네 파일 전체를 이전 상태로 자동 복구하지 않으며, 조회 측의 세대 검사와 기존 캐시 유지가 이를 보완합니다.

캐시가 새 데이터를 받아들이는 조건

manifest의 세대와 파일 서명을 확인하며 필요 시 SHA-256으로 내용을 검증합니다. 적재 전후 세대가 같고 로딩이 완료되었을 때만 메모리를 교체합니다. 실패하면 기존 캐시가 있는 경우 이를 유지하고 최초 적재 오류는 전파합니다. manifest가 없으면 파일 자체의 변경을 감지합니다.

데이터 의미와 연결 규칙

대상식별·해석 규칙
시설·강좌 집계이용현황의 시설 키는 지역 코드·시군구 코드·시설명·주소·상세주소입니다. 강좌는 여기에 강좌번호를 조합합니다. 식별할 수 없는 행은 제외 건수로 기록합니다.
신청인원개설월별 기록의 합계이며 고유 이용자 수가 아닙니다. 여러 기간을 더한 값을 현재의 수요나 참여 인구로 해석하지 않습니다.
시설↔교통정규화한 시설명 + 위도·경도 소수점 6자리. 교통 색인은 상세를 열 때 필요한 시점에 만들며 근거리 항목을 유지합니다.
종목↔시설SPORT_TYPES에 명시된 종목·시설유형/업종 대응과 지역·정상운영 조건을 사용합니다. 일반 체육관을 특정 종목 시설로 추정하지 않습니다.
누락값일반 숫자 변환 실패는 None, 잘못된 개설연월은 unknown. 자료 미제공과 관측된 0을 구분합니다.
인구·지원 대상·운영시간·시설 수용능력 등 비교 기준이 없어 이용 기록만으로 미충족 수요나 정책 효과를 확정할 수 없습니다.

운영 기본값과 배포 흐름

scripts/start_render.py는 migrate 실행 후 Gunicorn으로 전환합니다. 운영 구성은 1 worker, gthread 4 threads, timeout 180초입니다. CSV 메모리 캐시는 프로세스 단위이며 지역 AI 요약은 서버 파일 캐시입니다. AI 동시 실행 제한은 프로세스당 1건입니다.

CSV 세대 확인 주기 5초, 최초 준비 대기 기준 120초. 예약은 일요일 00:00이며 settings.TIME_ZONE=UTC를 사용합니다. 로컬 사용자 시간대와 예약 시간대를 혼동하지 않아야 합니다.

Python 표준 라이브러리 csv·json·threading·urllib 등이 CSV 처리, 동시성, 외부 정책 조회를 지원합니다. HTMX·ECharts는 로컬 번들로 제공됩니다. httpx·Pydantic 등은 AI SDK의 간접 의존성이며 직접 고정한 패키지 버전과 구분합니다.

Render Environment에 GEMINI_API_KEY를 등록하며 AI_MODE=live, AI_PROVIDER=gemini, AI_MODEL=gemini-3.1-flash-lite를 사용합니다. 로컬 .env는 Git에 포함되지 않습니다. AI_REGION start의 key_configured는 키 존재 여부이며 유효성 검증 결과는 아닙니다.

AI 분석·검토

조회한 CSV 통계와 사용자가 입력한 계획을 공통 인터페이스를 통해 AI 공급자(현재 Gemini)에 전달해 현황 해석과 보완 의견을 제공합니다. CSV 원본 전체를 업로드하거나 모델을 사전 학습하지 않습니다. AI는 참고 의견을 제공하며 최종 기획·운영 결정은 담당자가 합니다.

기능사용 흐름과 결과
지역현황 AI분석 요약대시보드 통계 아래 돋보기 버튼을 누르면 선택 지역의 요약·눈여겨볼 특징·기획 시 확인할 점을 표시합니다. 페이지 진입이나 지역 변경만으로 AI를 호출하지 않습니다.
프로그램 AI 검토프로그램 정보를 입력한 뒤 AI 검토 버튼을 누릅니다. 다이얼로그에서 진행 상태와 결과를 확인하고, 하단의 ‘계획서에 포함하기’를 선택한 뒤 확인 버튼으로 닫습니다.
계획서 반영선택한 검토 결과만 계획서에 포함합니다. 계획서 생성 시 AI를 다시 호출하지 않으며, 인쇄와 최근 5건 복원에도 생성 당시 결과가 유지됩니다. 입력이 변경되면 다시 검토해야 합니다.

공급자 교체 구조

지역 요약과 프로그램 검토는 AIRequest → AIProvider.generate → AIResponse 규약을 사용합니다. 현재 Gemini·더미 공급자를 구현했습니다. GPT·Claude는 전용 어댑터와 팩토리 등록 후 사용할 수 있으며 설정만으로 즉시 호출되지는 않습니다. 선택한 SDK만 로딩하고 공급자별 캐시를 분리하며 자동 공급자 전환은 하지 않습니다.

공통 호출 흐름과 모듈 확장 방법 
지역 현황 / 프로그램 검토
  → 업무 서비스: 근거 데이터 · 지침 · 응답 스키마 구성
  → AIRequest(task, instruction, evidence, schema, request_id)
  → factory.create_provider(): 모드 · 공급자 · 모델 선택
  → AIProvider.generate(): 공급자 SDK 호출 또는 더미 응답
  → AIResponse(data, provider, model)
  → 공통 검증 → 지역 캐시 / 검토 토큰 / 계획서

추가 공급자는 providers 아래에 어댑터를 구현하고 factory.PROVIDERS에 모듈·클래스·키 환경변수를 등록합니다. 응답 형식과 오류를 공통 규약으로 변환하며, 재시도는 어댑터 한 곳에서만 수행합니다. 업무 서비스의 점수 계산과 화면·서명 로직은 공유합니다.

현재 GPT·Claude 어댑터는 미구현입니다. 공급자 설정만 바꾸면 unsupported_provider로 처리하며 임의로 Gemini나 더미로 전환하지 않습니다. 더미도 실제 호출과 같은 응답 검증 경로를 사용합니다.

분석 근거와 판단 범위

지역 분석은 선택 구의 시설·강좌·신청 실적·종목별 분포·자료 기간을 사용합니다. 프로그램 검토는 여기에 선택 시설과 작성한 프로그램 정보를 더합니다. 근거가 있는 항목만 평가하며 인구·복지·총예산처럼 제공되지 않은 항목을 만들어 채우지 않습니다. 교통 분석은 별도 설정으로 활성화하며 기본값은 비활성입니다.

항목별 의견과 점수는 선택된 AI 공급자가 반환하고, 서버가 응답 형식과 근거 키를 검증한 뒤 평가 가능한 점수의 동일 가중 평균과 등급을 계산합니다. 모든 점수가 없으면 서버에서 ‘판단 자료 부족’을 표시합니다. 이용권 신청 실적은 고유 인원이나 지역 전체 수요가 아니며, 시설 등록 건수만으로 실제 공급 부족을 단정하지 않습니다.

로컬은 프로젝트 루트 .env에 저장 후 서버를 재시작합니다. Render는 해당 서비스의 Environment에 각각 등록하고 재배포합니다. 같은 이름의 변수는 기존 OS·Render 환경변수가 .env보다 우선합니다.

기존 AI_REVIEW_MODE=gemini/dummy, GEMINI_MODEL, GEMINI_TIMEOUT_SECONDS도 지원합니다. 대응하는 새 설정이 있으면 새 설정이 우선하므로 이행 후 기존 이름은 정리할 수 있습니다. 기존 키 이름은 유지합니다.
