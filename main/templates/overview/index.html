기획 목표와 현재 구현 범위

구분내용
기획 목표지역별 이용 통계를 근거로 공공시설을 활용한 스포츠 프로그램을 설계하고, 지역사회와 스포츠의 선순환을 만듭니다.
현재 구현담당자가 지역 통계를 확인하고 종목·시설·운영 정보를 직접 선택·입력하는 검토용 계획서 도구입니다. 생성형 AI 자동 기획이나 실제 개설 확정은 아닙니다.
지역·시설 범위기본 배치는 서울이며 대시보드 적재도 서울로 제한됩니다. 설계 후보는 지역·종목·정상운영 조건을 사용하고 공공시설 전용 조건은 없습니다.
보관 방식업무 조회 데이터는 CSV·메모리 캐시, 계획서는 브라우저 최근 5건입니다. Django 기본 SQLite 설정과 업무 데이터 저장은 구분됩니다.

패키지 책임과 유지보수 경계

View는 요청 검증과 응답, Service는 필터·집계, Model/Repository는 CSV 적재, Template은 화면 표시를 맡습니다.

planning/reports.py는 전달받은 통계와 입력으로 보고서를 구성하며 CSV를 다시 조회하지 않습니다. planning/snapshots.py는 결과 서명·검증을 담당합니다. 설계 Form과 후보 선정은 dashboard/planning.py에 남아 있습니다.

runtime/targets.py가 기능별 공개 갱신 함수를 조립하고, 실행 관리자는 캐시 내부 값에 직접 접근하지 않습니다. shared는 구체적인 업무 패키지를 import하지 않는 지역 선택 정책입니다.

시스템 아키텍처

Django 서버 렌더링에 HTMX 부분 갱신과 fetch 기반 설계를 결합합니다. 브라우저가 CSV를 직접 읽지 않고 서버가 가공한 HTML·JSON을 받습니다.

구성동작
화면과 요청HTML·HTMX·일반 JavaScript·ECharts. 별도 React 앱이나 DRF 중심 API 구조는 아닙니다.
적재와 갱신runtime이 목록을 사전 적재하고 세대 변경을 확인합니다. 완전한 적재 후 메모리를 교체하며, 갱신 중에는 기존 목록을 제공합니다.
기동 상태ready는 정상, loading/missing은 형식에 맞는 503. stalled는 요청을 통과시켜 직접 읽기를 허용합니다.
운영 구성Render 1인스턴스, Gunicorn 1워커·4스레드. WhiteNoise는 정적 파일, SQLite는 Django 기본 테이블을 담당합니다.
서버 기동·데이터 준비·저장 방식

워커 초기화 뒤 CSV 사전 적재와 스케줄러를 시작합니다. Gunicorn master 단계에서 갱신 스레드를 만들지 않아 fork 이후 잠금·스레드 불일치를 피합니다.

준비 상태는 최초 적재 완료 여부를 기준으로 판단합니다. 갱신 중에도 기존 목록이 있다면 ready 상태로 조회할 수 있습니다. loading·missing은 503, stalled는 요청을 통과시켜 직접 적재를 허용합니다.

파일별 캐시가 독립적이므로 한 요청이 여러 데이터셋의 동일 세대를 반드시 읽는 전역 트랜잭션 구조는 아닙니다. BATCH_STORAGE_MODE=db는 확장 지점이며 DB 모델·저장기·조회 전환이 완료되었다는 뜻은 아닙니다.

배치 검증과 세대 공개 과정

UTF-8 BOM을 허용해 원본을 읽고 필수 지역 열을 검사합니다. 짧은 행, 지역 코드 누락·비숫자 값·시도/시군구 코드 불일치를 제외하며 사유별 건수를 기록합니다. 대상 행이 0건이면 게시를 거부합니다.

독점 잠금 파일로 동시 실행을 제한하고 오래된 잠금은 6시간 기준으로 처리합니다. .part 작성 후 flush·fsync와 대상 범위 검증을 거쳐 파일을 교체합니다. manifest에는 generation·수정시각·크기·SHA-256·행 수·제외 건수가 담깁니다.

준비본 생성 실패 시 .part를 정리하고 로그를 남깁니다. 파일 교체 도중 장애는 네 파일 전체를 이전 상태로 자동 복구하지 않으며, 조회 측의 세대 검사와 기존 캐시 유지가 이를 보완합니다.

캐시가 새 데이터를 받아들이는 조건

manifest의 세대와 파일 서명을 확인하며 필요 시 SHA-256으로 내용을 검증합니다. 적재 전후 세대가 같고 로딩이 완료되었을 때만 메모리를 교체합니다. 실패하면 기존 캐시가 있는 경우 이를 유지하고 최초 적재 오류는 전파합니다. manifest가 없으면 파일 자체의 변경을 감지합니다.

데이터 의미와 연결 규칙

대상식별·해석 규칙
시설·강좌 집계이용현황의 시설 키는 지역 코드·시군구 코드·시설명·주소·상세주소입니다. 강좌는 여기에 강좌번호를 조합합니다. 식별할 수 없는 행은 제외 건수로 기록합니다.
신청인원개설월별 기록의 합계이며 고유 이용자 수가 아닙니다. 여러 기간을 더한 값을 현재의 수요나 참여 인구로 해석하지 않습니다.
시설↔교통정규화한 시설명 + 위도·경도 소수점 6자리. 교통 색인은 상세를 열 때 필요한 시점에 만들며 근거리 항목을 유지합니다.
종목↔시설SPORT_TYPES에 명시된 종목·시설유형/업종 대응과 지역·정상운영 조건을 사용합니다. 일반 체육관을 특정 종목 시설로 추정하지 않습니다.
누락값일반 숫자 변환 실패는 None, 잘못된 개설연월은 unknown. 자료 미제공과 관측된 0을 구분합니다.
인구·지원 대상·운영시간·시설 수용능력 등 비교 기준이 없어 이용 기록만으로 미충족 수요나 정책 효과를 확정할 수 없습니다.

상세 입력·결과 처리 흐름

지역: 지도·행정구역 선택 후 통계를 갱신하고 다음 단계에 선택 요약을 표시합니다. 시설: 종목·검색어로 후보를 조회하고 목록·상세 로딩을 별도로 관리합니다.

프로그램: 프로그램명, 시설별 모집인원, 수강료·단위, 대상, 운영 시작·종료일과 설명을 입력합니다. 서버는 날짜 순서·범위·시설 서명을 다시 검사합니다.

생성: 생성 당시 통계와 시설·입력 정보가 모달에 표시되고 설계 화면을 초기화합니다. 최근 결과는 서버 서명과 함께 저장되며 복원 때 서명을 확인합니다.

인쇄: 모달 내용을 일반 문서 영역으로 복사하고 이미지 디코딩을 기다린 뒤 출력합니다. 종료 후 인쇄용 복사본을 정리합니다. 문자·카카오톡은 공유 내용 확인과 안내 단계입니다.

초기화·자료 누락503 + no-store + Retry-After: 3. HTML 안내, JSON 오류, HTMX HX-Refresh, Excel 요청은 plain text로 응답합니다.

잘못된 설계 입력중복 없이 1~20개 시설, 날짜 순서·인원·금액 범위 검사. 후보가 있는데 시설 미정으로 우회하면 거부합니다.
시설 선택 변조·만료2시간 서명 토큰과 현재 후보의 ID·명칭·주소를 비교하고 다르면 재선택 안내를 합니다.
결과 손상서명·version·구조와 최대 1,000,000 길이 검사. 결과 서명에는 별도 만료시간이 없지만 키가 바뀌면 복원이 실패할 수 있습니다.
대량 Excel50,000건 초과는 거부하고 검색 조건 축소를 안내합니다. 문자열 셀 형식으로 전화번호 앞자리와 수식처럼 보이는 문자열을 보존합니다.
외부 정책 오류통신·인코딩·목록 구조 오류를 안내 문구로 바꾸고 성공/실패 캐시 기간을 구분합니다.
응답 역전·조회 실패listVersion/detailVersion으로 과거 응답 무시, fetch 오류 안내 후 로딩 해제. 생성 후 초기화 실패는 생성 성공과 구분합니다.

운영 기본값과 배포 흐름

scripts/start_render.py는 migrate 실행 후 Gunicorn으로 전환합니다. 운영 구성은 1 worker, gthread 4 threads, timeout 180초입니다. 캐시는 프로세스 단위입니다.

CSV 세대 확인 주기 5초, 최초 준비 대기 기준 120초. 예약은 일요일 00:00이며 settings.TIME_ZONE=UTC를 사용합니다. 로컬 사용자 시간대와 예약 시간대를 혼동하지 않아야 합니다.

Python 표준 라이브러리 csv·json·threading·urllib 등이 CSV 처리, 동시성, 외부 정책 조회를 지원합니다. HTMX·ECharts는 로컬 번들로 제공됩니다.
