이 프로젝트가 붙들고 있는 규칙

코드 전반이 일관되게 지키는 데이터 원칙이 있고, 화면 문구와 집계 함수가 모두 여기에 맞춰져 있다. 리팩터링할 때 가장 깨지기 쉬운 부분이기도 하다.

원칙구현 위치깨지면 생기는 일
결측 ≠ 0 ≠ 수록 대상 아님 _sum_known()은 아는 값만 더하고, 전부 없으면 None common/calculations.py · dashboard/services.py 미제공 시설이 0건으로 집계돼 지역 비교가 왜곡된다
시설↔교통은 좌표로만 연결 geo_key() = 정규화 시설명 + 좌표 6자리 facilities/transit.py 주소 체계가 달라 16%만 매칭되고, 동명 시설이 뒤섞인다
시군구는 관리 시군구를 쓴다 FCLTY_MANAGE_SIGNGU_NM facilities/models.py 단순 SIGNGU_NM은 7,503행이 도로명주소와 어긋난다
종목은 추정하지 않는다 SPORT_TYPES 16종, 시설유형·업종에 명시된 경우만 dashboard/planning.py 종합체육관을 농구장으로 간주해 없는 후보를 제시한다
삭제는 제외, 폐업은 표시 DEL_AT=Y 제외 · FCLTY_STATE_VALUE는 화면 필터 facilities/models.py 문 닫은 시설이 운영 중인 것처럼 목록에 오른다

데이터 정제 흐름

app/Batch/regional_csv_batch.py

원본을 그대로 읽으면 화면 한 번에 1GB를 훑어야 한다. 배치가 지역 행만 추려 서비스 CSV를 만들고, 네 파일이 모두 검증을 통과한 뒤에야 한꺼번에 교체한다. 교체 사실은 batch_manifest.json의 세대(generation)로 알린다.

  1. 원본 확인

    지역 판별 열(CTPRVN_CD 등)이 없으면 시작하지 않고 중단한다.

    4 파일 · 1,032 MB

  2. 추출 · 품질 계수

    시도 코드 우선, 이름은 보조. 코드 누락·형식 오류·주소 불일치를 각각 세어 남긴다.

    → *.part 로만 기록

  3. 검증

    네 준비본을 모두 검사한다. 행이 0건인 파일이 하나라도 있으면 전체를 반영하지 않는다.

    all-or-nothing

  4. 원자적 교체

    os.replace로 운영 파일을 바꾼다. 불완전한 파일이 노출되는 구간이 없다.

    → 213 MB · 486,556 행

  5. 세대 발행

    파일별 mtime·size·sha256·행수를 담은 manifest를 마지막에 원자적으로 쓴다.

    gen 2026-09-21_0

읽기 시점의 2차 정제

배치는 지역만 거른다. 값의 의미를 다듬는 일은 각 기능의 models.py가 메모리에 올리면서 수행하고, 무엇을 덜어냈는지 함께 센다. 그 수치는 화면 하단 출처 안내에 그대로 나온다.

대상처리남기는 기록
프로그램표시 항목이 전부 같은 행을 접는다. 기간은 YYYY-MM-DD로, <br> 태그는 공백으로 정규화중복 제거 건수, 자료가 담은 시설 수
시설DEL_AT=Y 제외. 도로명 → 지번 → 행정명 순으로 주소 결정 삭제 제외 건수, 폐업 수, 좌표 없어 미연결된 시설 수
이용현황시도·시군구별 고유 시설/강좌 집계. 식별 정보가 부족하면 제외 원장 행수, 식별 불가 행수, 관측 개설월 범위
대중교통좌표 기준 최근접 10개만 유지(KEEP=10). 직선거리로 정렬 수록 시설 수, 미연결 사유 4종
메모리 형태. 행은 dict가 아니라 namedtuple로 담는다. 29만 행 기준 약 80MB(tuple) 대 약 320MB(dict) 차이이고, 템플릿은 item.name 속성 접근이라 화면 코드는 그대로다.

웹은 요청마다 또는 5초마다 이 파일의 generation을 읽는다.

  • 같은 세대 → 메모리 재사용. 파일을 다시 읽지 않는다.
  • 새 세대 → 새로 읽어 완전히 끝난 뒤에만 교체한다. 그동안 요청은 옛 목록을 그대로 받는다.
  • 교체 중간 상태(CSV는 바뀌었는데 manifest는 아직) → DataGenerationPending. 이미 적재된 프로세스는 옛 목록 유지.
  • 배포로 mtime이 바뀐 경우 → 크기와 sha256으로 같은 파일임을 확인하고 통과시킨다.

계획서 작성 3단계

단계 이동은 전부 클라이언트 상태이고, 서버는 각 단계의 요청을 매번 독립적으로 검증한다.

  1. 종목 선택 · 후보 확인

    선택 지역에서 시설유형·업종에 그 종목이 명시된 정상운영 시설만 20개씩 불러온다. 공공/민간 구분 수를 함께 보여주고 감추지 않는다.

    후보 0건 → “자료에 종목이 명시된 시설이 없다”

  2. 시설 확정

    상세를 확인하며 최대 20곳을 고른다. 선택값은 [id, 시설명, 주소] 서명 토큰이라 자료가 바뀌면 다른 시설이 조용히 선택되지 않는다.

    토큰 유효 2시간 · 지역·종목 변경 시 선택 해제

  3. 프로그램 입력 · 생성

    프로그램명·대상·기간·모집인원·수강료를 입력하면 지역 KPI와 종목 신청인원을 붙인 계획서를 만든다. 인쇄는 브라우저 인쇄를 쓴다.

    DB·세션 저장 없음 · 브라우저 보관함에 최근 5건

최근 생성 목록. 결과는 서버가 서명한 스냅샷(program-plan-result-v1)으로 localStorage에 최대 5건 보관한다. 복원할 때 서버가 서명만 확인하며 CSV를 다시 조회하지 않는다 — 그래서 그때의 수치가 그대로 재현되고, 지금 자료로 슬쩍 바뀌지 않는다.

Backend

서버 · 적재

적재 실패 시 옛 목록 유지
새 CSV를 다 읽고 세대를 재확인한 뒤에만 메모리를 교체한다. 읽기 실패·세대 확인 실패는 기록하고 이전 목록을 계속 서비스한다. versioned_csv.get()
미준비 요청을 형식에 맞게 거절
HTMX 조각은 HX-Refresh, 설계 마법사는 JSON, .xlsx는 텍스트, 페이지는 안내 화면. 전부 503 · no-store · Retry-After. runtime/middleware.py
비어 있는 이유를 코드로 구분
인접 교통이 안 보이는 경우가 넷이다 — source(읽기 실패) · no_position(좌표 없음) · not_public(민간, 수록 대상 아님) · not_listed(공공인데 미수록). 화면 문구가 각각 다르다.
열 구조 변경 선확인
원본 열 이름이 바뀌면 스트리밍 읽기가 조용히 0건을 낸다. 읽기 전에 columns_present()로 확인해 “자료 없음”과 가르지 않는다.
반쯤 채운 색인은 쓰지 않는다
164만 행을 흘려 읽는 중 OSError·UnicodeError가 나면 None을 돌려준다. 절반짜리를 정상처럼 쓰면 수록된 시설조차 “기록 없음”이 된다.
내보내기 상한
5만 행을 넘으면 조용히 자르지 않고 건수를 적어 거절한다. 정책 문서가 잘린 채 나가는 편이 더 나쁘다. common/exports.py
외부 크롤러는 예외를 던지지 않는다
응답 크기 상한·타임아웃·타 호스트 링크 제거. 실패는 화면에 띄울 문구로 돌려준다. 성공은 15분, 실패는 1분만 캐시한다.
설계 선택값 위변조 방지
시설 선택은 [id, 시설명, 주소] 서명 토큰(2시간). 서명·정체·중복·개수를 모두 확인하고, 하나라도 어긋나면 재선택을 요구한다.

Frontend

브라우저

진행 안내와 오류를 분리
진행은 role="status"(#plan-status), 실패·거부는 role="alert"(#plan-error). 스크린리더가 둘을 다르게 읽는다.
늦게 도착한 응답 버리기
목록·상세 요청마다 버전을 매겨, 이전 요청의 응답이 나중에 도착하면 화면에 반영하지 않는다. listVersion · detailVersion
보관함 접근 실패를 기능 정지로 만들지 않음
localStorage 읽기·쓰기를 모두 감싸고, 실패하면 “보관함을 읽을 수 없습니다. 생성과 인쇄는 계속 사용할 수 있습니다”로 안내한 뒤 나머지는 그대로 동작시킨다.
보관 데이터 형식 검증
배열인지, 서명 문자열인지, 길이가 상한 이내인지, 날짜가 유효한지 확인한 뒤 5건만 받아들인다. 손상된 항목은 조용히 버린다.
입력 단계에서 미리 거르기
시작일·종료일이 서로의 경계가 되고, 시설 20곳 상한은 체크 즉시 되돌리며 이유를 알린다. 서버 거절을 기다리지 않는다.
지도 로드 실패 격리
ECharts·GeoJSON 로드 실패는 fail() 한 곳으로 모으고, 폰트 로드 실패는 기본 글꼴로 계속 그린다. 지도가 못 떠도 조회 기능은 살아 있다.
화면 전환 오버레이 안전장치
메뉴 이동 스플래시는 150ms 뒤 표시, 60초 안전 타임아웃, pageshow(뒤로가기 bfcache 포함)에서 해제.
초기화 안내의 재시도 한계
/readyz/를 3초 간격으로 최대 40회 확인하고, 넘으면 새로고침을 멈추고 관리자 확인 안내로 바꾼다. 끝나지 않는 새로고침을 만들지 않는다.

Data pipeline

정제 배치

전부 아니면 전무
네 파일을 .part로 만들어 모두 검증한 뒤에야 교체한다. 하나라도 실패하면 운영 파일은 그대로 두고 준비본을 지운다.
빈 결과 반영 거부
대상 지역 행이 0건인 준비본은 반영하지 않는다. 원본 열 이름이 바뀌어 아무것도 못 고른 상황이 “서비스 자료 0건”으로 배포되는 것을 막는다.
지역 판별 열 선확인
시도·시군구 코드 열이 없으면 추출을 시작하지 않고 어떤 열이 없는지 적어 중단한다.
제외 행을 숨기지 않고 센다
코드 누락 · 형식 오류 · 주소 불일치를 각각 세어 manifest에 남기고, 배치 화면의 변경 사항 표에 그대로 보여준다.
중복 실행 잠금
잠금 파일로 동시 실행을 막고, 6시간이 지난 잠금은 비정상 종료로 보고 해제한다.
세대는 마지막에 원자적으로
CSV 4개를 모두 바꾼 뒤 manifest를 .part → fsync → os.replace로 발행한다. 세대가 보이면 네 파일은 이미 완전하다.
교체 중간 상태 표시
CSV는 새것인데 manifest가 옛것인 짧은 구간은 DataGenerationPending으로 구분한다. 이미 적재된 프로세스는 옛 목록을 유지한다.
배포 mtime 변화 대응
배포가 수정시각을 바꿔도 크기와 sha256으로 같은 파일임을 확인해 통과시킨다. 해시는 파일 버전당 한 번만 계산한다.
아직 남아 있는 것. 시설·프로그램 ID가 파일 행 순서에 의존하므로(facility-{n}), 원본이 갱신되면 북마크한 주소의 facilityId가 다른 시설을 가리킬 수 있다. 대표 이미지도 ID 끝자리로 고르기 때문에 함께 재배치된다. 안정적인 식별 키 도입이 후속 과제다.
